1. Design overview
The program is a single-file modular console application. Each menu option is handled by its own function. Student records are stored as dictionaries inside a global list. This structure is simple and matches the level of the unit while still showing clear separation of responsibilities (add, view, search, update, delete, rank, report, file load/save).

Final mark is calculated as the average of three assessment marks. Grade is assigned using the same boundaries shown in the unit grading table (HD 85+, DN 75-84, etc.).

A recursive function (recursive_sum) is used only for calculating the total of all final marks. Highest, lowest and grade counts are done with ordinary for-loops so the requirement of “own loops” is satisfied.

2. File handling
Data is stored in data/students.csv. The program loads the file at start-up. If the file does not exist it creates a new one with the correct header and continues without crashing. On exit the current list is written back to the same file.

3. Input validation
Every input that can fail is checked in a loop:
- empty text is rejected
- non-numeric marks are rejected
- marks outside 0-100 are rejected
- duplicate student IDs are blocked when adding
- unknown IDs for update/delete show a clear message
